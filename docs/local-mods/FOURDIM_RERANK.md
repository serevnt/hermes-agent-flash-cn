## 1. 解决的问题

`lcm_grep` 原来只有三种排序：

| sort | 逻辑 | 问题 |
|---|---|---|
| `recency`（默认） | 按时间倒序 | 老但高度相关的内容永远排不上来 |
| `relevance` | BM25 排名 | 只认词频，短查询会命中一堆「提过这个词」的噪音 |
| `hybrid` | BM25 ÷ 时间衰减 | 需要 BM25 分数，summary 命中容易被压掉 |

**缺的是**：在「相关」和「新」之间做**确定性**权衡，并且优先给出信息密度高的结果。

openseek-lcm 的经验（README 明确写了）：**相似度召回默认关闭**，改用确定性打分。需求 4 采纳同一思路。

---

## 2. 四维定义与权重

```python
score = 0.4 × 覆盖度 + 0.3 × 短语命中 + 0.2 × 时效 + 0.1 × 来源种类
```

| 维度 | 算法 | 为什么 |
|---|---|---|
| **覆盖度** | 查询分词后，命中词数 / 总词数 | 命中越多词越相关；比 BM25 更抗「单个高频词刷分」 |
| **短语命中** | 完整查询出现=1.0；否则最长的命中子串给 0.3~0.6；英文多词全命中=0.6 | 「说了同一句话」比「提过同样的词」强得多 |
| **时效** | `2^(-age/7天)`，下限 0.15 | 半衰期 7 天，两个月前的内容仍有 0.15 底分，不会归零 |
| **来源种类** | summary=1.0 / message=0.7 / externalized=0.5 | 摘要是压缩过的信息，密度高，先看它更划算 |

### 2.1 中文分词（关键）

中文没有词边界。`_fourdim_terms()` 的做法：

- 英文/数字：`[a-z0-9_]+`，长度 ≥2
- **中文：按 2-gram 切**（`城市旅人` → `城市`、`市旅`、`旅人`）

2-gram 的好处：不需要词典，召回稳；坏处：会有 `市旅` 这种无意义组合，但因为**只是覆盖度的分母**，噪声影响有限。

### 2.2 短语命中的子串回退

最初实现只试「整段中文是否出现」，结果 `城市旅人视觉小说` 在 `城市旅人这个项目` 里得 **0 分**（因为整段不在）。

修正后按长度递减找最长命中子串：

```python
城市旅人视觉小说  vs  城市旅人这个项目
  length=7: 城市旅人视觉小  ✗
  length=6: 城市旅人视觉    ✗
  length=5: 城市旅人视      ✗
  length=4: 城市旅人        ✓  → 0.3 + 0.3×(4/8) = 0.45
```

**这是这轮唯一一次实现缺陷**（测试抓出来的，不是事后想起来的）。

## 3. 确定性怎么保证

| 风险 | 处理 |
|---|---|
| `time.time()` 在排序 key 里被调用多次 → 每次微变 | 调用点算**一次** `_fourdim_now`，作为参数传进 key |
| 浮点误差导致排序不稳定 | `round(score, 6)` 后再比较 |
| 相似度模型/LLM 引入随机性 | **完全不用**——纯字符串操作 |

**验证**：同一输入调用两次得分完全一致（`0.9697709159615261` vs `0.9697709159615261`）。

---

## 4. 只重排不筛选

需求原话：**「重排只决定先看哪几条，不决定给不给」**。

实现严格守这条：
- 排序发生在**截断之前**
- 候选集完全不变（还是 FTS/BM25 选出来的那些）
- 只是顺序变了

**副作用（正确行为）**：不同 sort 的**最终结果集**可能不同——因为截断发生在排序之后，排序变了，被截掉的条目也变了。这不是 bug。

## 6. 用法

```
lcm_grep(query="城市旅人", sort="fourdim")
```

**建议默认用 fourdim**：它对「找一个你知道说过什么、但不确定在哪次会话」的场景最友好。

其他 sort 保持原样，不影响既有行为。

---

## 7. 影响面

| 项 | 影响 |
|---|---|
| 既有 sort | 完全不变（新分支在 `if sort == "fourdim"` 里，前面的逻辑没动） |
| 非法 sort | 仍退回 recency（`normalize_search_sort` 只多认一个值） |
| 查询性能 | fourdim 比 recency **更快**（实测 2.36s vs 4.66s） |
| 索引/存储 | 无变化（纯排序层） |

## 9. 局限（写清楚，不粉饰）

1. **权重是我拍的**（0.4/0.3/0.2/0.1），没有大规模 A/B 数据支撑。要调就改 `_FOURDIM_W_*` 四个常量，不用动逻辑。
2. **2-gram 中文分词**对「同义不同词」（说「视觉小说」vs 说「galgame」）无能为力——这是纯字符串方法的固有边界，要解决只能上向量。
3. **来源种类权重偏低**（0.1），实际影响有限；如果发现 summary 该更优先，把它调到 0.2。
4. **降级链（Hindsight 优先 → LCM 兜底）没做在代码里**——那是调用侧的策略，不是检索层的能力。当前实现保证的是「LCM 兜底时结果排序够好」这一环。
